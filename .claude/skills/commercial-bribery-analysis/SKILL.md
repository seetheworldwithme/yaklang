# 商业贿赂犯罪资金分析
## 数据处理要求（强制）

执行本技能前，先使用 `excelcli-analysis` 完成文件导入、字段识别、标准化、筛选和基础统计。银行流水统一分析 `bank_transactions`；涉税数据统一分析 `tax_invoices`、`seller_invoice`、`buyer_invoice`、`tax_registrations` 等标准表。

本技能只规定查案思路、指标体系、模式识别、报告结构和调证建议；不要在技能中提供自定义代码示例，也不要指导智能体自行读取 Excel/CSV 或自建入库流程。


基于"打击商业贿赂犯罪'三定三破'技战法"的完整方法论。本技能提供分析框架、领域知识、判断规则和分析框架和报告要求，帮助你完成从数据探查到报告撰写的全流程。

核心分析逻辑：以"资金流"引导"犯罪流"，通过追踪资金流向、信息碰撞定位关联人、客观证据定性行受贿关系。[来源：技战法"三定三破"]

## 数据文件说明

典型的商业贿赂资金分析数据包含以下四类文件（文件名可能不同，以实际列名为准）：

### 1. 交易明细（主表）

核心数据文件，每条记录为一笔交易，包含收付双方完整信息。所有分析的主要数据来源。

**标准字段**：交易卡号、交易账号、交易户名、交易证件号、交易时间、交易金额、交易余额、收付标志（进/出）、交易对手账卡号、现金标志、对手户名、对手证件号、对手开户银行、摘要说明、交易币种、交易网点名称、交易发生地、交易是否成功、传票号、IP地址、MAC地址、对手交易余额、交易流水号、凭证号、交易柜员号、备注

### 2. 人员信息（辅助表）

涉案客户的身份和背景信息。**在商业贿赂场景中，该表是建立企业-个人关联网络、识别中间人和白手套的关键数据源**。通过工作单位、法人代表、单位地址、代办人等字段，可还原行受贿双方的职务关系和利益链条。[来源：技战法"三定三破"——信息碰撞定位]

**标准字段**：客户名称、证照类型、证照号码、单位地址、单位电话、工作单位、邮箱地址、代办人姓名、代办人证件类型、代办人证件号码、国税纳税号、地税纳税号、法人代表、客户工商执照号码

> **商业贿赂重点字段**：工作单位、法人代表、单位地址、代办人姓名/证件号码、客户工商执照号码 — 这些字段用于建立企业-个人关联网络，是识别行受贿关系的关键

### 3. 账户信息（辅助表）

涉案账户的开户属性和状态信息，用于报告"账户基本信息"章节。

**标准字段**：账户开户名称、开户人证件号码、交易卡号、交易账号、账号开户时间、账户余额、币种、开户网点代码、开户网点、账户状态、账户类型、备注、账号开户银行

### 4. 子账户信息（辅助表）

涉案账户的子产品/子类别信息（如定期、理财、贷款等），用于展示账户的完整资金结构。

**标准字段**：银行名称、开户账号、子账户账号、余额、可用余额、子账户类别、币种、钞汇标识、账户状态

> **文件匹配原则**：用户提供的文件可能名称不同，但通过列名可以识别文件类型。优先匹配交易明细，再通过"交易卡号/交易户名/证照号码"等关键字段关联辅助表。

## 分析框架

分析分为四个阶段，按顺序执行。每个阶段完成后检查产出是否齐全再进入下一阶段。

### 阶段A：数据探查与交易画像

**目标**：了解账户全貌，建立基础数据认知，识别交易渠道特征。

**操作**：读取数据文件，确认列名和数据格式，然后计算以下指标。

**首先检查账户数量**：读取交易明细后，先统计"交易卡号"列的唯一值数量，确认数据中涉及几个主体账户。如果只有1个账户则为单账户分析；如果有多个账户，需在报告开头列出所有涉案账户，后续分析分别或合并进行（取决于业务需求）。

**数据预处理**：
1. 过滤失败交易：如"交易是否成功"列存在，仅保留值为1（成功）的记录，并在报告中注明过滤了多少笔失败交易
2. 交易时间、金额、方向等字段由 `excelcli normalize` 标准化；如结果异常，先用 `excelcli inspect` 和 `import_issues` 核查字段映射
3. 收付方向通常在"收付标志"列，值为"进"/"出"，先确认具体取值
- 使用 `excelcli inspect "./output/analysis.db" --json --sample 3` 查看真实列名和样例数据。
5. 关联辅助表：通过"交易卡号"或"交易户名"关联账户信息和人员信息，补充账户属性和人员背景

**必须产出的指标**：
- 涉及主体账户数量（单账户/多账户）
- 交易笔数、交易总额、时间跨度（首尾日期和天数）
- 收入/支出分别的笔数和金额
- 收支比例（收入占比 / 支出占比，商业贿赂场景中受贿方通常收入远大于支出）
- 年度交易趋势（按年分组的进出笔数、金额、以及每年进出分别涉及多少个对手主体）
- 金额分布（按 0-1千/1千-5千/5千-1万/1万-5万/5万-10万/10万-50万/50万以上 共7个区间，分别统计进出笔数）
- 现金交易笔数、金额、占比（如数据中有"现金标志"列）
- 余额特征：最高/最低/平均/最终余额（如数据中有"交易余额"列）
- 日均交易笔数
- **交易渠道分析**：基于"现金标志"或交易摘要等字段，统计通过银行柜台、ATM、网上银行、POS机、第三方支付等不同渠道完成的交易笔数和金额占比。识别异常的渠道偏好（如大量通过第三方支付或网银完成的敏感交易）。[来源：技战法"三定三破"——核查在银行柜台、ATM机、网上银行、电话银行、POS机、支付宝等各种交易系统中留下的蛛丝马迹]
- **交易地理分布**：按"交易发生地"统计交易笔数和金额，识别主要交易地区（如数据中有该字段）
- **对手开户银行分布**：按"对手开户银行"统计对手账户数，识别资金主要流向的银行机构（如数据中有该字段）
- **账户开户信息**：从账户信息表汇总所有涉案账户的开户时间、开户网点、账户类型、账户状态等（如提供了账户信息文件）
- **子账户结构**：从子账户信息表展示涉案账户的子产品分布和资金分布（如提供了子账户信息文件）

### 阶段B：资金来源去向分析

**目标**：识别核心交易对手，刻画资金流向模式，初步建立行受贿关系假设。

**必须产出的指标**：
- 收入端涉及多少个不同对手账户
- 支出端涉及多少个不同对手账户
- TOP10资金来源表：对手账户、对手户名、对手证件号（用于关联人员信息）、交易笔数、总金额、平均单笔、特征标注
- TOP10资金去向表：同上
- 资金来源集中度：TOP1 / TOP3 / TOP5 占总收入的百分比
- 资金去向集中度：TOP1 / TOP3 / TOP5 占总支出的百分比
- 同名账户识别：对手户名与主体账户户名相同的账户列表及合计金额
- 双向交易对手：既有收入又有支出的对手账户
- 自身转账：对手账户号等于主体账户号的交易统计
- **贿赂伪装摘要识别**：检测摘要中包含"咨询费/技术服务费/顾问费/佣金/提成/奖金/好处费/感谢费/辛苦费/中介费/介绍费/茶水费/车马费/劳务费/信息费/协调费"等关键词的交易，统计笔数、金额、对手分布。[来源：技战法"三定三破"——资金流水定向]
- **行受贿关系初步识别**：通过人员信息表的工作单位、法人代表等字段，识别对手中是否存在与主体账户存在业务关系的企业或个人（如供应商、客户、承包商等）。紧扣"单位"和"个人"两大主体，分析对手的企业背景。[来源：技战法"三定三破"——信息碰撞定位]

**分析要点**：
- 对手信息分布在"交易对手账卡号""对手户名""对手证件号""对手开户银行"等列中
- 可通过"对手证件号"关联人员信息表，获取对手的工作单位、单位地址、法人代表等背景信息，用于判断是否存在业务关联
- 无对手信息的交易（NaN）单独统计，通常是现金存取——在商业贿赂场景中需特别关注大额现金存入
- TOP10表中的"特征"列可标注：同名账户、企业账户、关联企业、贿赂伪装摘要、单向转入、大额整数等
- 注意识别"企业账户向个人账户"的单向转账模式，这是行贿的典型资金流

### 阶段C：关联人网络分析

**目标**：通过设备指纹、人员信息碰撞、代办人关联、亲属推断等维度，识别行受贿关联人网络和白手套账户。[来源：技战法"三定三破"——信息碰撞定位]

**子任务C1 — 基于设备信息的关联识别**：

IP/MAC地址在交易明细中直接可用，无需单独的对手数据文件：

1. 从交易明细中提取所有支出方向（收付标志="出"）的交易记录
2. 在出账记录中，统计每个IP/MAC地址涉及的"交易卡号"数量（即不同账户出账时使用同一设备）
3. **关键**：只有在出账方向上共享同一IP/MAC的账户才视为设备关联
4. 使用 Union-Find 算法：在出账记录中共享同一IP或MAC的账户归为同一关联组
5. 输出每个关联组的成员、共享IP数、共享MAC数、与主体账户的交易金额

**子任务C2 — 基于对手证件号前6位的地域聚合**：

如交易明细中有"对手证件号"列：
1. 提取对手证件号前6位（代表户籍所在地区划代码）
2. 将相同前6位的对手账户归为同一地域组
3. 身份证前6位相同意味着来自同一地区，在商业贿赂场景中可能提示同乡/同族关联
4. 统计每个地域组的成员数和与主体的交易金额
5. 也可结合人员信息表中的"工作单位""单位地址"进行交叉验证

**子任务C3 — 基于人员信息的企业-个人关联网络构建**：[来源：技战法"三定三破"——信息碰撞定位]

如提供了人员信息表：
1. **工作单位碰撞**：将工作单位相同的不同客户归为同一企业关联组，分析同单位人员与主体账户的交易模式
2. **法人代表碰撞**：如对手中有多人的法人代表相同，说明同属一个利益集团
3. **单位地址碰撞**：不同客户的单位地址相同/相近，可能为关联企业
4. **工商执照号码关联**：相同工商执照号码指向同一企业
5. **邮箱碰撞**：不同客户使用相同邮箱，提示隐性关联
6. 综合以上碰撞结果，构建企业-个人关联网络图

**子任务C4 — 基于代办人信息的账户关联**：[来源：技战法"三定三破"——信息碰撞定位]

如人员信息表中有"代办人姓名"和"代办人证件号码"：
1. 统计同一代办人代办的不同账户数
2. 代办人代办 >= 2 个账户视为可疑关联
3. 检查代办人本人是否也有交易记录（代办人可能就是中间人）

**子任务C5 — 亲属与同事关系推断**：[来源：技战法"三定三破"——信息碰撞定位]

1. **亲属推断**：对手证件号前6位与主体证件号前6位相同（同户籍地），且出生年份相近（证件号第7-10位），可能为亲属
2. **同事关系**：通过人员信息表的工作单位字段，识别与主体在同一单位任职的对手
3. 受贿人的亲属或同事账户如果出现与行贿方的交易，可能是代收贿赂的"白手套"

**子任务C6 — 白手套账户识别**：[来源：技战法"三定三破"——客观证据定性]

1. 从C5中识别出的亲属/同事账户中，检查其是否同时与行贿方存在交易关系
2. 中间人/白手套账户的典型特征：进出对手极少（一进一出），充当纯粹的资金通道
3. 如果某账户的进账来自行贿方、出账流向受贿方关联人，则高度可疑

**数据缺失处理**：
- 如果交易明细中没有IP/MAC列：跳过C1，仅做C2-C6
- 如果没有对手证件号列：跳过C2和C5中的亲属推断部分
- 如果没有人员信息表：跳过C3、C4、C5中的同事关系部分
- 不要因为部分数据缺失而放弃整个关联人分析章节

### 阶段D：可疑特征量化与研判

**目标**：对前三阶段的发现进行量化评估，形成行受贿关系的证据链。

计算以下可疑指标（详见下方"可疑指标与阈值"），逐项给出数值和判定结论，作为报告"可疑点分析"章节的依据。完成后根据指标组合匹配"经营模式识别规则"，推断可能的商业贿赂类型。[来源：技战法"三定三破"——客观证据定性]

## 可疑指标与阈值

以下是商业贿赂犯罪的核心可疑指标。分析时逐项计算，每项给出具体数值和判定结论。

| 序号 | 指标名称 | 计算方法 | 说明 | 异常阈值 |
| --- | --- | --- | --- | --- |
| 1 | 贿赂伪装摘要笔数 | 摘要含"咨询费/技术服务费/顾问费/佣金/提成/奖金/好处费/感谢费/辛苦费/中介费/介绍费/茶水费/车马费"的笔数 | 商业贿赂常以合法商业名目伪装 | >= 1 |
| 2 | 大额现金存入笔数 | 现金标志为现金 且 收付标志为进 且 金额 >= 5万的笔数 | 受贿后现金存入银行 [来源：技战法"三定三破"——即使现金形式，仍然可能存在大额存现] | >= 1 |
| 3 | 异常大额进账 | 单笔进账金额超过同方向平均金额3倍以上的笔数 | 与正常收入模式不匹配的大额收入 | >= 3 |
| 4 | 单向资金关系对手占比 | 仅有单方向（只进或只出）交易的对手数 / 总对手数 | 正常商业关系通常有双向资金往来，单向提示可能为贿赂 | > 70% |
| 5 | 整额交易占比 | 整万金额交易笔数 / 总笔数 | 贿赂款多为整数金额 | > 30% |
| 6 | 非工作时间交易占比 | 22:00-08:00或周末/节假日的交易笔数 / 总笔数 | 规避监督的时间选择 | > 15% |
| 7 | 企业转个人占比 | 对手为企业账户（对手户名含"公司/有限/集团/厂"等）且收付标志为进的金额 / 总收入金额 | 企业向个人大额转账是行贿典型模式 | > 40% |
| 8 | 关联企业对手数 | 对手中工作单位/法人代表/单位地址存在重叠的不同对手个数 | 同一利益集团通过多个主体行贿 [来源：技战法"三定三破"——信息碰撞定位] | >= 3 |
| 9 | 代办人重叠账户数 | 同一代办人代办的不同账户数 | 通过代办人控制多个账户隐藏资金 [来源：技战法"三定三破"——信息碰撞定位] | >= 2 |
| 10 | 收入与支出时间差异 | 大额进账后短期内（7天内）等额或近似额支出的配对数 | 收到贿赂后快速转移/消费/投资 | >= 3 |
| 11 | 资金来源集中度 | TOP3收入金额 / 总收入 | 少数对手集中转入提示特定利益关系 | > 60% |
| 12 | 同单位对手集中度 | 来自同一工作单位的对手数 / 总对手数 | 同一公司多人行贿提示组织化行贿 [来源：技战法"三定三破"——串并案分析] | > 20% |

补充指标（如数据支持，建议也计算）：
- 自身转账笔数和金额占比（存在且金额占比 > 5% 视为异常）
- 大额现金存入的时间规律性（固定周期/固定金额）
- 交易渠道异常偏好（如敏感交易集中使用某一渠道）
- **地域集中度**：对手证件号前6位相同的人数占总对手数的比例（> 30% 视为异常）
- **开户银行集中度**：TOP1开户银行的对手账户数 / 总对手账户数（> 40% 视为异常）

## 经营模式识别规则

根据可疑指标的组合，匹配以下商业贿赂犯罪模式。可能同时符合多种模式，逐一判断。

**模式一：采购回扣型行贿**：
- 受贿方为有采购权限的企业人员
- 行贿方（供应商）向受贿方个人账户转账，摘要为"咨询费""技术服务费""佣金"等
- 转账时间与采购订单/合同签订时间相关
- 资金流特征：企业账户 → 个人账户，单向为主
- 金额特征：多为整数，与采购金额可能存在固定比例关系
- 关联指标：企业转个人占比高、贿赂伪装摘要、单向资金关系

**模式二：销售佣金型行贿**：
- 行贿方为销售人员或销售公司
- 向客户方有决策权的人员私人账户转账
- 资金流特征：个人或企业 → 受贿个人，可能通过中间人中转
- 金额特征：与销售合同金额呈比例
- 关联指标：资金来源集中度高、整额交易占比高

**模式三：中间人/白手套型行贿**：
- 行贿方不直接向受贿方转账，而是通过中间人/亲属账户中转
- 中间人账户特征：几乎只有进出两个方向的对手（一进一出），充当资金通道
- 中间人可能是受贿方的亲属（证件号前6位相同）或朋友
- 资金流特征：行贿方 → 中间人 → 受贿方关联人
- 关联指标：代办人重叠账户、关联企业对手、收入与支出时间差异

**模式四：现金贿赂型**：
- 受贿方账户出现不明来源的大额现金存入 [来源：技战法"三定三破"——即使现金形式，仍然可能存在大额存现]
- 现金存入金额呈规律性（固定周期、固定金额）
- 现金存入时间可能与行贿方账户大额取现时间匹配
- 存现地点可能远离受贿方常住地/工作地
- 关联指标：大额现金存入笔数、非工作时间交易

**模式五：多主体分散行贿型**：
- 多个不同行贿方向同一受贿方或其关联人转账
- 这些行贿方之间可能存在关联（同行业、同地区、同供应商名录）[来源：技战法"三定三破"——串并案分析]
- 受贿方收到多笔来自不同对手的类似金额/类似摘要的转账
- 通过串并案可发现受贿的系统性
- 关联指标：关联企业对手数、同单位对手集中度、单向资金关系

**模式六：项目节点型行贿**：
- 资金集中在特定时间节点（如招投标前后、项目验收前后、合同签订前后）
- 多笔资金在短时间窗口内流入
- 事后可能有"感谢费""辛苦费"等名义的后续转账
- 关联指标：贿赂伪装摘要、异常大额进账、时间集中度

匹配到模式后，在报告中按"行贿路径四层模型"描述行受贿资金链条：
1. **行贿资金来源层**：行贿方的资金从哪里来（企业账户/个人资金）
2. **资金中转层**：是否经过中间人/白手套中转
3. **受贿资金接收层**：受贿方或其关联人如何接收（转账/现金存入/第三方支付）
4. **资金消化层**：受贿资金的最终去向（消费/投资/转移/存储）

## 常见问题处理

分析过程中遇到问题时参考以下指引，不要卡住。

### 数据列名不匹配

不同系统导出的交易数据列名差异很大。先打印列名再适配：

使用 `excelcli inspect` 查看真实字段和样例数据；使用 `excelcli transactions`、`excelcli tax invoices` 或 `excelcli query` 完成筛选和统计。

常见列名对照（与本项目标准字段的映射）：

| 标准字段 | 可能的其他列名 |
| --- | --- |
| 交易卡号 | 卡号、账号、账户号码、主账号 |
| 交易账号 | 账号、内部账号、账户号 |
| 交易户名 | 户名、账户名称、客户姓名 |
| 交易证件号 | 证件号码、身份证号、身份证号码、证件号 |
| 交易时间 | 交易日期、记账时间、发生日期 |
| 交易金额 | 金额、发生额、交易发生金额 |
| 收付标志 | 借贷标志、交易方向、借贷方向 |
| 交易余额 | 余额、账户余额、当前余额 |
| 交易对手账卡号 | 对手账号、对方账户、对手卡号 |
| 对手户名 | 对方户名、对方姓名、对手名称 |
| 对手证件号 | 对手身份证号、对方证件号码 |
| 对手开户银行 | 对手银行、对方开户行、对手开户网点 |
| 交易发生地 | 交易地点、发生地、地区 |
| 交易网点名称 | 交易网点、网点名称、机构名称 |
| 交易是否成功 | 成功标志、交易状态、处理状态 |
| 现金标志 | 交易渠道、转账方式 |
| 摘要说明 | 摘要、交易摘要、备注、用途 |
| IP地址 | IP、登录IP、操作IP |
| MAC地址 | MAC、设备MAC、物理地址 |

如果找不到对应列，跳过依赖该列的分析项，在报告中注明"因数据中缺少XX字段，该项未分析"。

### Excel文件过大或读取失败

使用 `excelcli inspect` 查看真实字段和样例数据；使用 `excelcli transactions`、`excelcli tax invoices` 或 `excelcli query` 完成筛选和统计。

### 分析结果异常

排查步骤：先用 `excelcli inspect` 核对列名和样例，再查看 `import_issues` 与映射文件；必要时调整映射后重新标准化。

常见问题：
- 金额、时间、空值等解析问题优先查看 `import_issues`，必要时调整 `mapping.json` 后重新标准化。

### 分析结果不符合预期

- **收支严重不平衡**（如只有进没有出）：在商业贿赂场景中，受贿方账户可能确实以收入为主，这反而是可疑特征。但仍需检查收付标志列的取值是否正确识别
- **对手全部为NaN**：可能现金交易没有对手信息，在商业贿赂场景中特别关注大额现金存入
- **年度统计金额与总额对不上**：检查是否有交易金额为0的记录或异常值
- **交易笔数与预期不符**：检查是否已过滤"交易是否成功" != 1 的失败交易
- **人员信息表匹配率低**：可能对手证件号格式不统一或有脱敏处理，尝试模糊匹配

### 数据量过少（<100笔）

- 年度趋势改为按季度或月度统计
- 金额分布合并为3个区间（小额/中额/大额）
- 关联人分析简化为仅做同名账户、企业关联和直接交易关系分析
- 大额进账后短期转移改为逐笔检查而非统计天数
